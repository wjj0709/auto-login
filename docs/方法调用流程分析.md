# AnyRouter Auto Check-in 方法调用流程分析

> 从 `main` 入口出发，完整分析 Rust 主程序与 Python 子脚本的调用链路和逻辑

---

## 1. 项目概览

| 项目 | 说明 |
|------|------|
| 包名 | `anyrouter-checkin` |
| 语言 | Rust（主程序）+ Python（Playwright 子脚本） |
| 入口 | `src/main.rs` → `async fn main()` |
| 目的 | 多账号自动签到 + 余额监控 + 邮件通知 |

### 文件结构

```
src/
├── main.rs          # 程序入口，流程编排
├── config.rs        # 配置加载（Provider / Account）
├── playwright.rs    # 调用 Python 子进程执行签到
├── checkin.rs       # 签到结果格式化（通知消息 / 用户信息摘要）
├── balance.rs       # 余额哈希检测（判断余额是否变化）
├── notify.rs        # 邮件通知
└── log.rs           # 日志工具模块
scripts/
└── playwright_checkin.py   # Playwright 签到子脚本
```

## 2. main() 完整调用流程

```
main()
 ├── dotenvy::dotenv()                          # 加载 .env
 ├── AppConfig::load_from_env()                 # [config.rs] 加载 Provider 配置
 ├── load_accounts_config()                     # [config.rs] 加载账号配置
 ├── load_balance_hash()                        # [balance.rs] 加载上次余额哈希
 ├── playwright::run_checkin()                  # [playwright.rs] → Python 子进程签到
 │    ├── locate_script()                       #   定位脚本文件路径
 │    ├── locate_python()                       #   获取 Python 解释器路径
 │    ├── build_account() × N                   #   为每个账号构建入参
 │    ├── Command::new(python).arg(script)      #   启动 Python 子进程
 │    ├── stdin.write_all(payload_json)         #   通过 stdin 传入 JSON
 │    └── 解析 stdout JSON → Vec<PlaywrightResult>
 ├── 遍历签到结果，统计成功/失败            # main 内循环
 ├── generate_balance_hash()                    # [balance.rs] 生成当前余额哈希

 ├── NotificationKit::from_env()                # [notify.rs] 初始化通知
 │    └── EmailNotifier::from_env()             #   邮件配置加载
 └── notify.push_message()                      # [notify.rs] 发送邮件通知
      └── email.send()                          #   SMTP 发送
```

### 3.2 阶段 2：Playwright 签到（Rust → Python 子进程调用）

**这是整个项目最核心的部分，涉及 Rust 主程序与 Python 子脚本的跨进程通信。**

#### 3.2.1 `playwright::run_checkin()` — Rust 端

**文件**: `src/playwright.rs:125-239`

**调用链**:
```
run_checkin(accounts, providers)
 ├── 遍历 accounts，按 provider 匹配，构建 Vec<PlaywrightAccount>
 │    └── build_account(account, provider, index)
 │         ├── 从 account.cookies 中提取 _username / _password（兼容写法）
 │         └── 回退读取环境变量 ANYROUTER_USERNAME_N / ANYROUTER_PASSWORD_N
 │
 ├── 构建 JSON payload:
 │    {
 │      "headless": bool,
 │      "timeout_ms": 30000,
 │      "accounts": [PlaywrightAccount...]
 │    }
 │
 ├── locate_script()     # 定位 Python 脚本路径
 │    ├── 优先: PLAYWRIGHT_SCRIPT 环境变量
 │    ├── 其次: CARGO_MANIFEST_DIR/scripts/playwright_checkin.py
 │    ├── 再次: 可执行文件目录的祖先目录下寻找
 │    └── 兜底: 当前工作目录下 scripts/playwright_checkin.py
 │
 ├── locate_python()     # 获取 Python 解释器
 │    └── PYTHON_BIN 环境变量，默认 "python3"
 │
 ├── headless_flag()     # 读取无头模式配置
 │    └── PLAYWRIGHT_HEADLESS != "0"/"false"/"False" → true
 │
 ├── Command::new(python).arg(script)
 │    .stdin(Stdio::piped())
 │    .stdout(Stdio::piped())
 │    .stderr(Stdio::inherit())      ← stderr 输出到主进程终端
 │    .spawn()
 │
 ├── stdin.write_all(payload_json)   ← 通过 stdin 传入 JSON
 ├── stdin.shutdown()                 ← 关闭 stdin，通知子进程读取完毕
 │
 ├── child.wait_with_output()         ← 等待子进程执行完毕
 │
 ├── 解析 stdout JSON 为 PlaywrightOutput
 │    pub struct PlaywrightOutput {
 │        results: Vec<PlaywrightResult>,
 │        error: Option<String>,
 │        message: Option<String>,
 │    }
 │
 └── 返回 Ok(Vec<PlaywrightResult>)
```

**`PlaywrightAccount` 结构**（传入 Python 的账号数据）:
```rust

    pub name: String,
    pub provider: String,
    pub domain: String,
    pub login_path: String,

    pub username: Option<String>,

```

#### 3.2.2 Python 子脚本 `scripts/playwright_checkin.py` — 详细流程

**文件**: `scripts/playwright_checkin.py`

**入口**: `main()` → 读取 stdin JSON → `asyncio.run(run(payload))`

```
main()
 ├── sys.stdin.read()                       # 从 stdin 读取 JSON
 ├── json.loads(raw)                        # 解析 payload
 └── asyncio.run(run(payload))              # 异步执行签到
      │
      ├── 解析 headless, timeout_ms, accounts
      ├── async_playwright() → 启动 Playwright
      ├── chromium.launch_persistent_context()
      │    user_data_dir=tempdir             ← 临时目录，退出即清除
      │    headless=True/False
      │    user_agent=CHROME_UA              ← 伪装 Chrome 138 UA
      │    args: disable-blink-features, disable-dev-shm-usage, no-sandbox
      │
      └── 逐个账号处理: for acc in accounts
           └── process_account(context, acc, timeout_ms)
                │
                ├── parse_cookies(acc.cookies)
                │    └── 支持 dict 和 "k1=v1; k2=v2" 字符串两种格式
                │
                ├── context.add_cookies()     ← 注入 Cookie
                │
                ├── context.new_page()        ← 创建新页面
                │
                ├── page.goto(login_path)     ← 访问登录页（获取 WAF cookie）
                │    └── acw_tc / acw_sc__v2 / cdn_sec 等 WAF cookie
                │
                ├── 检查 session cookie 是否存在
                │    └── 若不存在 + 有账密 → perform_login()
                │         ├── POST /api/user/login?turnstile=
                │         ├── body: {"username": ..., "password": ...}
                │         └── 使用 page.evaluate(fetch) 在浏览器上下文中执行
                │              └── fetch_in_page() — 封装浏览器内 fetch 请求
                │
                ├── call_user_info() 【签到前】
                │    ├── GET {domain}/api/user/self
                │    ├── headers: Accept, Content-Type, X-Requested-With, {api_user_key}
                │    ├── fetch_in_page() — 浏览器内 fetch
                │    ├── normalize_quota() — 原始值 / 500000 转为美元
                │    └── sanitize_user_info() — 过滤敏感字段
                │
                ├── call_sign_in() 【签到】
                │    ├── sign_in_path 为 None → 自动签到，跳过
                │    └── sign_in_path 有值 → POST {domain}{sign_in_path}
                │         ├── headers: 同上
                │         ├── body: ""
                │         ├── fetch_in_page() — 浏览器内 fetch
                │         └── 判断成功条件:
                │              ├── ret == 1 / code == 0 / success == true
                │              ├── msg 含 "已经签到"/"已签到"/"重复签到" 等关键词 → 也算成功
                │              └── 其他 → 失败
                │
                ├── call_user_info() 【签到后】
                │    └── 同签到前，获取最新余额信息
                │
                └── page.close()
                     └── 返回 AccountResult
```

**Python 核心函数说明**:

| 函数 | 作用 |
|------|------|
| `main()` | 入口：读 stdin JSON → 调用 `run()` → 写 stdout JSON |
| `run(payload)` | 创建浏览器上下文，逐账号调用 `process_account()` |
| `process_account()` | 单账号签到全流程：注入 Cookie → 访问首页 → 登录 → 签到前查询 → 签到 → 签到后查询 |
| `perform_login()` | 用账密调用登录 API 获取 session cookie |
| `call_user_info()` | 调用 /api/user/self 获取用户信息和余额 |
| `call_sign_in()` | 调用签到 API（manual 签到的 Provider） |
| `fetch_in_page()` | 在浏览器 JS 上下文中执行 fetch，复用浏览器 TLS 和 Cookie |
| `parse_cookies()` | 解析 Cookie（支持 dict 和分号分隔字符串） |
| `normalize_quota()` | 余额原始值 / 500000 转为美元单位 |
| `sanitize_user_info()` | 过滤 token/secret/password 等敏感字段 |
| `build_api_headers()` | 构建 API 请求头（含自定义 api_user_key） |

```
┌─────────────┐                    ┌──────────────────────┐
│  Rust 主程序  │                    │  Python 子脚本         │
│  main.rs     │                    │  playwright_checkin.py│
└──────┬───────┘                    └───────────┬──────────┘
       │                                        │
       │  stdin: JSON payload                   │

       │                                        │  asyncio.run(run())

       │                                        │  1. 注入 Cookie

       │                                        │  3. (可选) 登录

       │                                        │
```

### 3.3 阶段 3：余额变化检测

**文件**: `src/main.rs:186-235` + `src/balance.rs`

```
余额变化检测流程:
 ├── generate_balance_hash(&current_balances)
 │    ├── balances → BTreeMap 排序（保证一致性）
 │    ├── serde_json::to_string() 序列化
 │    ├── SHA-256 哈希
 │    └── 取前 16 位 hex 作为哈希值
 │
 ├── 比对 last_balance_hash 与 current_balance_hash
 │    ├── 无上次哈希 → 首次运行，balance_changed=true
 │    ├── 哈希不同 → 余额变化，balance_changed=true
 │    └── 哈希相同 → 无变化
 │
 └── save_balance_hash(hash)
      └── 写入 balance_hash.txt
```

**哈希设计**: 使用 `BTreeMap` 而非 `HashMap` 排序，确保相同数据生成相同哈希。

## 5. 脚本调用机制详解

### 5.1 脚本定位策略

`locate_script()` 函数按优先级查找 Python 脚本：

| 优先级 | 来源 | 说明 |
|--------|------|------|
| 1 | `PLAYWRIGHT_SCRIPT` 环境变量 | 显式覆盖路径 |
| 2 | `CARGO_MANIFEST_DIR/scripts/playwright_checkin.py` | 编译时项目根目录（最可靠） |
| 3 | 可执行文件目录的祖先目录 | 适配部署场景 |
| 4 | 当前工作目录下 `scripts/playwright_checkin.py` | 兜底 |

### 5.2 Python 解释器选择

`locate_python()` 函数：
- 优先使用 `PYTHON_BIN` 环境变量
- 默认使用 `python3`

### 5.3 通信协议

- **Rust → Python**: 通过 `stdin` 传入 JSON
- **Python → Rust**: 通过 `stdout` 返回 JSON
- **Python 日志**: 通过 `stderr` 直接输出（Rust 端设置 `Stdio::inherit()`）

### 5.4 Python 脚本中的核心网络请求

所有 API 请求均通过 `fetch_in_page()` 在**浏览器 JS 上下文**中执行，而非直接 HTTP 请求。这样做的原因是：

1. **TLS 握手**：浏览器原生完成 TLS，指纹正常
2. **WAF 通过**：绕过反爬虫检测（acw_tc / acw_sc__v2 等 WAF cookie）
3. **Cookie 复用**：浏览器的 `credentials: 'include'` 自动携带 Cookie

`fetch_in_page()` 实现原理：
```python
async def fetch_in_page(page, url, method, headers, body=None):
    # 在 page.evaluate 中执行 JS fetch
    js = """
    async ({ url, method, headers, body }) => {
        const init = { method, headers, credentials: 'include', cache: 'no-store' };
        if (body !== null) init.body = body;
        const resp = await fetch(url, init);
        const text = await resp.text();
        return { ok: true, status: resp.status, body: text };
    }
    """
    return await page.evaluate(js, {url, method, headers, body})
```

```
    │                               │←────────────签到结果──────────│
    │                               │                              │
    │                               │  call_user_info()──────GET──→│ /api/user/self
    │                               │←────────────最新余额──────────│
    │                               │                              │
    │  ──stdout: JSON──────────────←│  page.close()                │
    │                               │  context.close()             │
    │                               │                              │
    │  解析签到结果                   │                              │
    │  生成余额哈希                   │                              │
    │  比对+保存哈希                  │                              │
    │  发送邮件通知（如需）            │                              │
    │  exit(0/1)                    │                              │
```

## 8. 关键设计决策

1. **Rust + Python 混合架构**：Rust 负责配置加载、流程编排、通知；Python + Playwright 负责浏览器自动化签到。通过 stdin/stdout JSON 通信，松耦合。

2. **浏览器内 fetch**：所有 API 请求都在 Chromium 的 JS 上下文中执行，利用浏览器的 TLS 和 Cookie 管理，绕过 WAF 和反爬机制。

3. **哈希对比余额变化**：用 SHA-256 前 16 位 hex 对余额数据做签名，只在余额变化时发送通知，避免重复打扰。

4. **多 Provider 支持**：内置 `anyrouter`（手动签到）和 `agentrouter`（自动签到），通过 `PROVIDERS` 环境变量可扩展自定义站点。

5. **双登录策略**：优先使用 Cookie（`session`），Cookie 失效时自动回退账密登录（`_username` / `_password`）。
